# Loading-time tests — GraphDB

Measures how each GraphDB ruleset affects loading time and materialisation
size. GraphDB materialises inferences on commit, so the time a load takes
includes the whole forward-chaining step.

## Contents

| Path | Description |
|---|---|
| `code/benchmark_rulesets.py` | Generic benchmark: one fresh repository per ruleset and run. Also hosts the GraphDB REST client reused by `reasoning-capability-test/graphdb/code/compare_implicit.py`. |
| `code/ecmo-graphdb-benchmark.sh` | Runs the benchmark on the ECMO ontology. |
| `code/make_dul_variants.py` | Generates the lighter DUL variants in `data/dul-variants/` (needs rdflib). |
| `data/dul-variants/` | `DUL-lite.ttl`, `DUL-flat.ttl` (committed). |
| `data/ecmo-deps/` | DUL and d0, downloaded on first use with `--dul` (git-ignored). |
| `results/` | One CSV per benchmark run (see [Results](#results)). |

All default paths are relative to the scripts, so the commands below work from
any directory. They are written as run from this folder.

## Generic benchmark

`benchmark_rulesets.py` repeats the following for every ruleset:

1. Create a fresh repository `bench-ruleset-<ruleset>`.
2. Load the ontology files, if any, timing them separately.
3. Load the data files.
4. Record explicit, inferred and total statement counts.
5. Delete the repository.

The `reasoning-test-*` repositories used by the reasoning-capability tests are
never touched. Standard library only.

The `rdfsplus` rulesets are excluded because they don't apply `rdfs:domain`
and `rdfs:range` (see the
[reasoning-capability findings](../../reasoning-capability-test/graphdb/README.md#findings-so-far)).

```bash
python code/benchmark_rulesets.py                       # university.ttl, 11 built-in rulesets (all but rdfsplus*), 1 warm-up + 3 runs
python code/benchmark_rulesets.py --ontology onto.ttl --data data1.ttl data2.nt.gz -n 5
python code/benchmark_rulesets.py --rulesets empty rdfs-optimized owl-horst-optimized owl2-rl-optimized --keep
python code/benchmark_rulesets.py --disable-sameas      # GraphDB's own default; affects horst/max/rl
python code/benchmark_rulesets.py --check-inconsistencies
```

Each run is written to `results/benchmark_rulesets_<timestamp>.csv` (or set it
with `-o`). The script then prints the median load time, standard deviation,
slowdown compared with `empty`, and the ratio of inferred to explicit
statements for each ruleset. owl:sameAs handling is enabled by default, as in
the test repositories.

The default data is `reasoning-capability-test/graphdb/data/university.ttl`,
which loads in milliseconds, so use a larger dataset to get meaningful timings.
Gzipped files are decompressed on the fly. A `.owl`/`.rdf`/`.xml` file that
fails to parse as RDF/XML is retried as Turtle (DUL.owl is Turtle); the failed
attempt is excluded from the timing. The repository config uses the GraphDB
10.x vocabulary.

## ECMO

`ecmo-graphdb-benchmark.sh` runs the benchmark on the ECMO release in
`JRC/ecmo/0.3.1_audited` (the `ecmo` repository next to this one; change it
with `--ecmo DIR`). It loads every ECMO module and the alignments as the
ontology, and the unit-test case fixtures as data (`--no-data` to skip).
DUL and d0 are not loaded unless you pass `--dul`: GraphDB doesn't follow
`owl:imports`, so the script then downloads them once into `data/ecmo-deps/`.

```bash
code/ecmo-graphdb-benchmark.sh                          # sameAs on and off, with data, 10 runs
code/ecmo-graphdb-benchmark.sh --sameas off --no-data   # one mode, ontology only
code/ecmo-graphdb-benchmark.sh --dul                    # also load DUL and d0
code/ecmo-graphdb-benchmark.sh --dul-lite               # DUL without transitive/symmetric associatedWith
code/ecmo-graphdb-benchmark.sh --dul-flat               # DUL without any transitive/symmetric property
code/ecmo-graphdb-benchmark.sh --consistency            # also check consistency
code/ecmo-graphdb-benchmark.sh -n 1 --rulesets empty rdfs-optimized owl2-ql-optimized owl-horst-optimized owl-max-optimized owl2-rl-optimized
```

### DUL variants

Full DUL makes `dul:associatedWith` transitive and symmetric. Almost every
ECMO property is a subproperty of it, so the rulesets with transitivity
(owl-horst, owl-max, owl2-rl) materialise an `associatedWith` clique of about
16.8M triples. `data/dul-variants/` holds two lighter versions generated by
`code/make_dul_variants.py`:

| Variant | Removed |
|---|---|
| `DUL-lite.ttl` | `associatedWith` transitivity, symmetry and its self-inverse axiom (`owl:inverseOf associatedWith`, which also entails symmetry) |
| `DUL-flat.ttl` | the same for every DUL property: no transitive, symmetric or self-inverse property is left |

Everything else (hierarchy, domains and ranges, inverses between distinct
properties, chains, disjointness) is kept. Use them with `--dul-lite`,
`--dul-flat`, or any other file with `--dul-file FILE`.

```bash
python code/make_dul_variants.py                        # download DUL, write data/dul-variants/
python code/make_dul_variants.py data/ecmo-deps/DUL.owl
```

### Consistency checks

With `--consistency` (`--check-inconsistencies` in `benchmark_rulesets.py`)
the repositories are created with consistency checks enabled. GraphDB then
rejects any commit that fires a consistency rule; the run is reported as
`INCONSISTENT` with the rule name, and the CSV gets `consistent=False` and the
full message in `error`. Only rulesets that contain consistency rules can
detect anything, so `empty` and `rdfs*` always pass.

ECMO + DUL + the case fixtures is inconsistent; the full analysis is in
[`reasoning-capability-test/graphdb/results/ecmo-inconsistencies.md`](../../reasoning-capability-test/graphdb/results/ecmo-inconsistencies.md).

ECMO contains about 3.7k `owl:sameAs` links, mostly in `ecmo-ph.ttl`, so it is
worth comparing both sameAs modes.

## Results

CSV columns: `ruleset, run, warmup, onto_load_s, data_load_s, total_load_s,
explicit, inferred, total, inferred_ratio, consistent, error`.

File names:

- `benchmark_rulesets_<timestamp>.csv` — generic benchmark;
- `ecmo_benchmark_sameas-<on|off>_<data|nodata>[_<dul variant>][_consistency]_<timestamp>.csv`
  — ECMO benchmark.

Both patterns are git-ignored. Files renamed with a `settingN-` prefix are not
matched, so they are tracked; the settings are:

| File | sameAs | Data | DUL | Consistency |
|---|---|---|---|---|
| `setting1-…_sameas-off_nodata_no-dul_20261007_122401.csv` | off | no | no | no |
| `setting2-…_sameas-off_nodata_consistency_20261007_145436.csv` | off | no | no | yes |
| `setting3-…_sameas-off_nodata_dul-lite_20261007_154905.csv` | off | no | DUL-lite | no |
| `setting4-…_sameas-off_nodata_dul-lite_consistency_20261007_160823.csv` | off | no | DUL-lite | yes |
